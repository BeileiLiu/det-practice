# 重构迁移路线

## 原则

- 每次迁移一条可用流程，不进行一次性重写。
- 先建立行为基线，再改结构；每一批都可回退。
- 先校正可信度和安全问题，再做视觉升级。

## 批次

| 批次 | 范围 | 可验收结果 |
|---|---|---|
| 0 | 基线审计、官方规则差异、产品原型 | 本文档集；测试基线明确 |
| 1 | `AppSession` + 听写纵向流程；服务器静态白名单 | 同一答案只提交一次；`server.env` 无法通过 HTTP 读取 |
| 2 | 当前规则清单；停止展示过时“官方流程”；去除模拟代答 | 无操作不产生答案；所有考试文案有版本依据 |
| 3 | 迁移 RS/FIB/FIBW；统一客观反馈结构 | 四个客观题型使用同一会话和结果契约 |
| 4 | 音频录制与转写分离；迁移口语题型 | 可以回听，转写可修正，无证据维度不评分 |
| 5 | 迁移互动阅读、互动听力、互动写作和考试状态机 | 阶段切换由流程层驱动，刷新和退出行为明确 |
| 6 | 首页、反馈、报告和复习页视觉实现 | 形成“今日任务 → 作答 → 复练”闭环 |
| 7 | 数据 schema 升级、旧代码删除、文档收口 | 旧数据可迁移，重复全局状态移除 |

## 批次 1 的完成条件

- `tests/session.test.js` 覆盖生命周期和重复提交。
- 听写手动提交与超时使用相同提交函数。
- 作答历史包含会话 ID、起止时间和提交原因。
- Python 服务器只提供允许公开的静态资源。
- 单测和整站冒烟通过。
